## Provider and model layers

`effect/ai` defines the provider-neutral services. Provider packages supply clients and model implementations. The client normally depends on an HTTP implementation and reads credentials through Config.

```ts
import { OpenAiClient, OpenAiLanguageModel } from "@effect/ai-openai"
import { Config, Effect, Layer } from "effect"
import { LanguageModel } from "effect/ai"
import { FetchHttpClient } from "effect/http"

const ClientLayer = OpenAiClient.layerConfig({
  apiKey: Config.Redacted("OPENAI_API_KEY")
}).pipe(Layer.provide(FetchHttpClient.layer))

const ModelLayer = OpenAiLanguageModel.model("gpt-4.1").pipe(
  Layer.provide(ClientLayer)
)

const summarize = Effect.fn("summarize")((text: string) =>
  LanguageModel.generateText({ prompt: `Summarize the following text:\n${text}` }).pipe(
    Effect.map((response) => response.text)
  )
)

const program = summarize("Release notes go here").pipe(Effect.provide(ModelLayer))
```

The model ID is illustrative; choose one available from the configured provider and suitable for the task. Do not recreate the provider client on every request.

Inside a service layer, `yield* modelLayer.captureRequirements` captures its client requirements during acquisition. Provide the resulting model layer to individual methods. This keeps provider requirements out of the public domain service interface while retaining layer-level dependency checking.

## Generation APIs

| API | Use and result |
|-----|----------------|
| `LanguageModel.generateText({ prompt })` | Text generation; inspect `.text`, `.finishReason` and `.usage` |
| `LanguageModel.generateObject({ prompt, schema, objectName })` | Validated structured output; decoded result is `.value` |
| `LanguageModel.streamText({ prompt })` | Stream response parts, not just strings |

```ts
import { LanguageModel, type Response } from "effect/ai"
import { Effect, Schema, Stream } from "effect"

const Summary = Schema.Struct({
  title: Schema.NonEmptyString,
  actions: Schema.Array(Schema.String)
})

const structured = LanguageModel.generateObject({
  objectName: "summary",
  prompt: "Summarize the meeting notes as a title and actions.",
  schema: Summary
}).pipe(Effect.map((response) => response.value))

const textDeltas = LanguageModel.streamText({ prompt: "Write a brief release note." }).pipe(
  Stream.filter((part): part is Response.TextDeltaPart => part.type === "text-delta"),
  Stream.map((part) => part.delta)
)
```

A schema validates the decoded response; it does not guarantee the model's claim is true. Preserve usage and finish information when it matters for budgets, truncation or diagnostics. Stream consumers should handle termination and cancellation, and avoid collecting unbounded responses unnecessarily.

## Tools and toolkits

Tool definitions contain the public contract. Handlers are a separate layer, so they can depend on application services and be substituted in tests.

```ts
import { Effect, Schema } from "effect"
import { LanguageModel, Tool, Toolkit } from "effect/ai"

const Search = Tool.make("Search", {
  description: "Find catalogue items by name",
  parameters: Schema.Struct({ query: Schema.NonEmptyString }),
  success: Schema.Array(Schema.Struct({ id: Schema.String, name: Schema.String })),
  failureMode: "error"
})

const Tools = Toolkit.make(Search)

const ToolsLayer = Tools.toLayer(Effect.gen(function*() {
  return Tools.of({
    Search: ({ query }) => Effect.succeed([{ id: "item-1", name: query }])
  })
}))

const answer = Effect.gen(function*() {
  const toolkit = yield* Tools
  return yield* LanguageModel.generateText({
    prompt: "Find a replacement filter",
    toolkit,
    toolChoice: "required"
  })
}).pipe(Effect.provide(ToolsLayer))
```

The example handler is a stub; real handlers call services acquired while building `ToolsLayer`. A model layer is still required to run `answer`.

`failureMode: "error"` propagates tool failures in the calling Effect's error channel. `"return"` captures them in tool results for the model to see. Choose deliberately, and declare appropriate failure schemas when tools expose typed failures.

`response.toolCalls` contains tool names, IDs and decoded parameters. `response.toolResults` contains corresponding results and an `isFailure` flag. Keep IDs when correlating calls and results; do not infer identity from execution order.

Provider-defined tools, such as tools exported by `OpenAiTool`, execute on the provider side. They can join a Toolkit without a local handler. User-defined tools still need the handler layer.

## Stateful chat

`Chat.empty` creates a new session; `Chat.fromPrompt` creates one with initial history/system content. `session.generateText` maintains history, including tool call/results, across turns. `session.history` is a Ref; read it with `Ref.get`.

Use a separate session per conversation or task. Putting one Chat instance in an application-wide layer shares its history among all callers unless that sharing is intentional. Serialise turns for a session, or explicitly define how concurrent turns are handled.

Use `session.exportJson` and `Chat.fromJson` to persist/restore chat state. Treat exported history as potentially sensitive data. Restoring a history does not by itself resume a model request that was interrupted in flight.

## Agent loops

A single generation call can invoke tools and return their results, but may still require another model turn to produce a final answer. Drive that loop explicitly when needed; do not use an unbounded `while (true)` in production.

```ts
import { DateTime, Effect, Schema } from "effect"
import { Chat, Tool, Toolkit } from "effect/ai"

class StepLimit extends Schema.TaggedError<StepLimit>()("StepLimit", {}) {}

const ClockTools = Toolkit.make(Tool.make("CurrentTime", {
  description: "Get the current UTC time",
  parameters: Schema.Struct({}),
  success: Schema.String
}))
const ClockToolsLayer = ClockTools.toLayer(Effect.succeed(ClockTools.of({
  CurrentTime: () => Effect.map(DateTime.now, DateTime.formatIso)
})))

const agent = Effect.fn("agent")(function*(question: string) {
  const tools = yield* ClockTools
  const session = yield* Chat.fromPrompt([
    { role: "system", content: "Use the available tools to answer the question." },
    { role: "user", content: question }
  ])
  for (let step = 0; step < 8; step++) {
    const response = yield* session.generateText({ prompt: [], toolkit: tools })
    if (response.toolCalls.length === 0) return response.text
  }
  return yield* new StepLimit()
})

const reply = agent("What time is it?").pipe(Effect.provide(ClockToolsLayer))
```

Provide a model layer to `reply`, as in the provider example. Set time/token/cost limits as well as a step limit, and handle interruption. Tools that mutate external state need authorisation and idempotency appropriate to that operation; model retries do not supply those guarantees.

## Execution plans and reason errors

`ExecutionPlan.make({ provide: modelA, attempts: 3 }, { provide: modelB, attempts: 2 })` describes retries and fallback across model layers. Use `Effect.withExecutionPlan(plan)` around generation; capture the plan's requirements in the service layer when necessary.

A provider fallback can repeat tool-bearing calls or generation that already produced partial output. Decide which operations are safe to retry and what the user sees before enabling automatic fallback.

`AiError` has structured reasons. A domain error can use `reason: AiError.AiErrorReason`, preserving rate limits, quota and safety failures. Recover with `catchReason`, `catchReasons` or `unwrapReason` rather than comparing formatted error messages. Honor provider retry information and bound retries; do not turn a refusal into an infinite provider loop.
